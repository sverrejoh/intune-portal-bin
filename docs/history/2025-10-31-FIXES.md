# Microsoft Intune on Arch Linux - Complete Fix Guide

## What Was Broken

The original issue: "Error Something went wrong. [4kv4v]" during authentication.

## Root Causes Discovered

1. **Corrupted gnome-keyring files** (`Default_keyring.keyring`)
   - Caused by switching to "unlock on login" keyring configuration
   
2. **Missing login keyring collection**
   - Microsoft Identity Broker (native C++ version 2.0.3) requires `/org/freedesktop/secrets/collection/login`
   - System only had `Default` and `Default_keyring` collections
   
3. **lsb_release reporting "Arch Linux"**
   - Overrode the Ubuntu spoof in `/etc/os-release`
   - Microsoft Intune only supports Ubuntu officially
   
4. **Missing TPM access**
   - User not in `tss` group for `/dev/tpm0` and `/dev/tpmrm0` access
   
5. **tpm2-tss version incompatibility**
   - Version 4.1.3 causes issues
   - Requires downgrade to 3.2.0-1
   
6. **Missing OpenSSL compatibility shim**
   - Intune calls `X509_REQ_set_version()` with invalid version (2 instead of 0)
   - OpenSSL 3.4+ enforces RFC 2986 compliance
   
7. **Missing dependencies**
   - OpenSSL 1.1 required for device broker
   
8. **Missing intune-daemon wrapper**
   - Package only created wrappers for portal and agent, not daemon

## Complete Fix Applied

### System Configuration
```bash
# 1. Add user to tss group for TPM access
sudo usermod -aG tss $USER

# 2. Disable lsb_release (breaks Ubuntu spoof)
sudo mv /usr/bin/lsb_release /usr/bin/lsb_release.bak

# 3. Downgrade tpm2-tss to 3.2.0-1
curl -LO "https://archive.archlinux.org/packages/t/tpm2-tss/tpm2-tss-3.2.0-1-x86_64.pkg.tar.zst"
sudo pacman -U tpm2-tss-3.2.0-1-x86_64.pkg.tar.zst

# 4. Pin tpm2-tss version
echo "IgnorePkg = tpm2-tss" | sudo tee -a /etc/pacman.conf

# 5. Install OpenSSL 1.1 compatibility
yay -S openssl-1.1
```

### Keyring Configuration
```bash
# 1. Fix corrupted keyring
systemctl --user stop gnome-keyring-daemon.service
rm ~/.local/share/keyrings/Default_keyring.keyring
systemctl --user start gnome-keyring-daemon.service

# 2. Create login keyring collection
cp ~/.local/share/keyrings/Default_keyring.keyring ~/.local/share/keyrings/login.keyring
echo "login" > ~/.local/share/keyrings/default
systemctl --user restart gnome-keyring-daemon.service

# 3. Verify login collection exists
busctl --user tree org.freedesktop.secrets | grep login
```

### Intune Installation
```bash
# 1. Install correct versions
yay -S intune-portal-bin-1.2511.7 microsoft-identity-broker-bin-2.0.3

# 2. Compile and install OpenSSL shim
gcc -shared -fPIC -o openssl_shim.so openssl_shim.c -lssl -lcrypto
sudo mkdir -p /opt/microsoft/intune/lib
sudo cp openssl_shim.so /opt/microsoft/intune/lib/

# 3. Create wrapper scripts for all binaries
for binary in intune-portal intune-agent intune-daemon; do
  sudo mv /opt/microsoft/intune/bin/${binary} /opt/microsoft/intune/bin/${binary}.original
  sudo tee /opt/microsoft/intune/bin/${binary} > /dev/null << 'WRAPPER'
#!/bin/bash
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
export LD_PRELOAD="/opt/microsoft/intune/lib/openssl_shim.so:${LD_PRELOAD}"
export GNOME_KEYRING_CONTROL=/run/user/$(id -u)/keyring
BINARY_NAME="$(basename "$0")"
exec "${SCRIPT_DIR}/${BINARY_NAME}.original" "$@"
WRAPPER
  sudo chmod +x /opt/microsoft/intune/bin/${binary}
done

# 4. Create registration.toml symlink
mkdir -p ~/.local/state/intune
ln -s ~/.config/intune/registration.toml ~/.local/state/intune/registration.toml

# 5. Ensure state directories exist
mkdir -p ~/.local/state/microsoft-identity-broker

# 6. Start services
sudo systemctl enable --now microsoft-identity-device-broker.service
sudo systemctl enable --now intune-daemon.service
systemctl --user enable --now intune-agent.timer
```

### Environment Setup
```bash
# Set keyring environment for systemd user services
export GNOME_KEYRING_CONTROL=/run/user/$(id -u)/keyring
systemctl --user set-environment GNOME_KEYRING_CONTROL=/run/user/$(id -u)/keyring
```

## Why It Works Now

1. **Login keyring** - Native C++ broker 2.0.3 specifically requires the "login" collection for libsecret operations
2. **OpenSSL shim** - Intercepts X509_REQ_set_version() calls and fixes invalid version (2→0)  
3. **TPM access** - tss group membership + downgraded tpm2-tss allows device key generation
4. **Ubuntu spoof** - Disabled lsb_release ensures Microsoft sees Ubuntu 24.04
5. **All wrappers** - Environment variables (LD_PRELOAD, GNOME_KEYRING_CONTROL) properly set for all components

## Final Working Configuration

- **OS**: Arch Linux (spoofed as Ubuntu 24.04.2 LTS)
- **intune-portal**: 1.2511.7
- **microsoft-identity-broker**: 2.0.3-1 (native C++)
- **tpm2-tss**: 3.2.0-1 (pinned)
- **openssl**: 3.x with openssl_shim.so compatibility layer
- **openssl-1.1**: Installed for device broker
- **Keyring**: gnome-keyring with "login" collection as default
